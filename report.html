1. Introduction

1.1 Project Objective

5alasly (an Arabic term meaning "Consider it done") is a hyper-local service coordination platform. Our mission is to transform how communities interact by providing a high-trust, low-friction environment for task delegation and skill sharing.

In a world where specialized help is often just a neighbor away, 5alasly provides the digital bridge. Whether it's emergency plumbing, physics tutoring, or moving assistance, the platform ensures that the right "helper" meets the right "client" in seconds.

1.2 Problem Domain

Fragmentation

Local services are often scattered across social media or physical ads, making them hard to verify.

Lack of Trust

Hiring strangers for sensitive home tasks requires a robust verification and rating system.

Communication Barriers

Real-time coordination is often lost in external messaging apps with no task context.

Invisibility

Talented individuals in the community often have no way to reach their immediate neighbors.

1.3 Target Audience

  • Local Homeowners: Seeking quick, reliable repairs or moving assistance.
  • Students: Looking for academic tutoring or offering skills for extra income.
  • Freelancers: Offering digital or physical services to local clients.
  • Active Seniors: Contributing through specialized knowledge or light assistance.

2. Core Features: Dashboard & Discovery

2.1 The Intelligent Home Dashboard

The Dashboard acts as the user's primary "Cockpit". It synthesizes complex real-time data into digestible metrics and provide immediate access to the community exchange.

Key Dashboard Components:

  • Metric Strips: Real-time counters for "Completed Tasks", "Monthly Engagement", and "Reputation".
  • Search-to-Filter Engine: A powerful contextual search bar that updates as you type.
  • Category Quick-Buttons: One-tap filtering for specific domains (Cleaning, Tutoring, etc.).

2.2 Search & Discovery Dynamics

The search functionality is not just a text filter—it's a discovery tool. It prioritizes results based on proximity and urgency (Urgent First / Nearest).

Example: Searching for "Cleaning" instantly isolates the relevant community requests while maintaining the global dashboard context.

5. Technical Architecture

5.1 Modern Frontend Stack

The application is built on **Angular v21**, utilizing the latest reactive patterns.

  • Angular Signals: We use a signal-driven state for the chat messages and contact lists. This eliminates the need for expensive change detection cycles and ensures the UI remains liquid-smooth.
  • Standalone Components: The architecture is fully modular, allowing for independent testing and lazy-loading of heavy modules like the Admin Dashboard.
  • Tailwind CSS Ecosystem: Custom design tokens provide a unified theme across all 15+ components.
// Example Signal-Driven State Management
export class ChatComponent {
  chatContacts = signal<ChatContactDTO[]>([]);
  selectedUser = signal<ChatContactDTO | null>(null);
  
  selectUser(user: ChatContactDTO) {
    this.selectedUser.set(user);
    this.loadConversation(user.id);
  }
}

5.2 Robust Backend Services

Powering the experience is a structured **Spring Boot (Java 17)** backend.

Database: Relational JPA for integrity in financial (budget) and schedule data.

WebSockets: STOMP/SockJS protocols for robust bidirectional messaging.

Security: Stateless authentication protecting user privacy and service records.

6. UI/UX Design Philosophy

6.1 Glassmorphism & Depth

We chose a "Light Glass" aesthetic for 5alasly. This involves high-transparency containers with heavy backdrop filters (`backdrop-blur-xl`), which communicates a sense of modernism and transparency—core values of the platform.

6.2 Responsive Profile Management

Profiles are designed to be "Action Hubs", showing deep analytics and task history through a refined tabbed interface.

User stats are calculated using rolling averages and real-time task completion audits.

6.3 Accessibility & Typography

Using the **Outfit** font for headings provides a geometric, welcoming feel, while **Inter** ensures maximum legibility for dense data displays (like task descriptions and budget numbers).
